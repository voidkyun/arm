# Documentation conventions

Keep the root README a minimal entry point for developers. Include a short
project description, prerequisites, the commands to build, test and start the
sample, one request that verifies startup, and a link to the docs index.

When reviewing a README addition, ask whether a developer needs it to reach
that first successful request. Put optional setup, configuration, further API
examples, design rationale and validation procedures in the relevant guide
under `docs/`. Link new guides from [the docs index](docs/README.md). When a
guide already covers a topic, update it there and avoid copying it into the README.
